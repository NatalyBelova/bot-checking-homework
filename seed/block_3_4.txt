Блок 3–4: Git, CI/CD, Kibana/Grafana, Linux, Kafka, Docker, SQL, DBeaver. Ученик присылает все скриншоты блока одной отправкой (обычно 20–25 скриншотов).

Принимать, если по каждой теме есть скриншот с выполненным заданием:

Git
- В терминале выполнены команды git branch -a, git log --oneline (видна история коммитов) и git pull в склонированном репозитории; видны вывод команд и текущая ветка.

CI/CD
- В GitLab открыт упавший job (failed), видны лог job и строка ошибки (например, «ERROR: Job failed: exit code 1»). Ученик указал номер job и причину ошибки (на скриншоте, в тексте или в файле).

Kibana
- В Kibana (Discover) выполнен поиск по trace.id, видны найденные документы/спаны запроса (operationName, код ответа и т.п.).

Grafana
- Открыт дашборд Grafana с панелями графиков (видны названия панелей и данные).

Linux
- В терминале выполнены команды по работе с файлом логов: переход в каталог (cd, pwd), создание файла (touch), поиск строк (grep), просмотр последних строк (tail -n), удаление (rm) и проверка (ls). Виден вывод команд.

Kafka
- В Kafka UI виден список топиков, среди них свой топик ученика (с его именем, например qa_имя_дата).
- В своём топике отправлены сообщения: видна вкладка Messages с несколькими сообщениями (offset, timestamp, key/value).

Docker
- В терминале запущен контейнер (docker run -d -p … nginx), виден docker ps с этим контейнером в статусе Up и docker logs.
- В Docker Desktop (или docker compose ps) видно приложение из нескольких контейнеров (например, веб-сервер nginx и база postgres), контейнеры запущены.

SQL (тренажёр) — 11 задач, по скриншоту на каждую: виден текст запроса и результат выполнения.
- Блок 1: фильтрация WHERE с AND; фильтрация с IN.
- Блок 2: DISTINCT с ORDER BY; сортировка по убыванию с LIMIT.
- Блок 3: GROUP BY с COUNT; GROUP BY с HAVING по AVG.
- Блок 4: INNER JOIN двух таблиц; LEFT JOIN с COUNT и GROUP BY.
- Блок 5: подзапрос в WHERE … IN (SELECT …); UPDATE с предварительной проверочной выборкой SELECT.
- Блок 6 (финальная): LEFT JOIN users–orders с агрегатами COUNT, AVG, MAX по пользователю и сортировкой.
Запрос считается верным, если решает задачу по смыслу и выполнился без ошибки (есть таблица результата).

DBeaver
- В DBeaver создано подключение к учебной базе, написан запрос с JOIN двух таблиц, виден результат в таблице.

Возвращать на доработку, если:
- нет скриншотов по какой-то теме блока (назови, какой именно);
- в SQL не хватает задач или запрос явно не решает задачу (например, нет GROUP BY там, где нужна группировка; нет JOIN там, где нужно соединение; запрос с ошибкой и без результата);
- в Kafka не видно своего топика или сообщений в нём;
- в Docker контейнер не запущен (нет статуса Up / running);
- в CI/CD не указана причина падения job;
- скриншот нечитаемый или обрезан так, что не видно запроса/вывода команды.

Неважно: конкретные данные в результатах (числа, имена, даты), формат записи SQL (регистр, отступы, алиасы), ОС и терминал, тема оформления, порядок скриншотов, имя топика и содержимое сообщений, название репозитория.
Частые ошибки: в SQL присылают только запрос без результата; в Kafka — только список топиков без сообщений; в Docker — только docker run без docker ps.
